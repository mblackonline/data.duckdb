About, Data Use & Acceptable Use

Last updated: October 25, 2026

This proof of concept explores CARTA's public datasets through reports, filters, and an AI assistant. Public reports require no sign-in. AI features require Microsoft sign-in and explicit authorization.

Public reports and downloads

Public report queries run in your browser using DuckDB and retrieve data from public sources. CSV exports are downloaded to your device. Data sources and hosting services process the network requests needed to provide this service.

Microsoft sign-in and cookies

Microsoft handles authentication. This application does not receive your Microsoft password. Microsoft's sign-in library temporarily caches account information, including your display name and authentication tokens, in this browser tab's session storage. This lets the app restore your sign-in after a page refresh. It sends an access token to its backend to verify your identity and AI permissions again before enabling AI.

Sign out to clear this app's cached sign-in for the current tab, especially on a shared device. Session storage normally lasts until the tab or window closes, but browser restore features may restore a previous session. Microsoft may also require you to sign in again when a session expires or organizational policy requires it. See Microsoft's sign-in cache documentation.

Microsoft uses cookies on its sign-in domains to manage authentication and sign-in sessions. Whether a session continues after you close your browser depends on your sign-in choices, browser settings, and organizational policies.

Microsoft Entra stores account or guest-account information, access assignments, and consent records. Its sign-in logs can include your account identifier, sign-in time, application, outcome, IP address, approximate location, and browser or device information. Appropriately authorized tenant administrators can access these records. Retention depends on the tenant's licensing and logging configuration. Read Microsoft's information about sign-in cookies, sign-in logs, and log retention.

AI requests and Groq

The assistant uses OpenAI's open-weight gpt-oss models hosted by Groq. Groq is the provider processing these AI requests.

AI requests pass through this site's backend to Groq. The backend uses the operator's server-held Groq API key, and usage is attributed to the operator's Groq account. Your Microsoft password, sign-in token, and account identifier are not sent to Groq for authentication or added to the AI prompt by the application.

Groq receives your question, selected table schemas, public dataset sample values, and other available table names. If a query needs correction, database error text is also sent and can include SQL or data values. Information you include in your question is shared with Groq. Generated SQL runs in your browser.

Do not submit passwords, API keys, personal information, confidential material, or other sensitive information to the AI assistant.

Use only public information in your questions. A question can disclose sensitive details about people or internal operations even when the requested report uses public data. Review your question before submitting it.

Application storage and provider retention

Aside from the browser sign-in cache described above, this application does not create or update persistent user profiles, user hashes, per-user quota counters, report-correction records, or AI activity history. Account information, tokens, questions, and responses are processed temporarily to provide the current session and requests. The application does not save them in a backend database or application logs.

There are no application-enforced per-user daily or minute quotas. The browser attempts one automatic SQL correction if a generated query fails. Provider and hosting limits still apply. Any usage records created by an earlier version remain until the deployment operator removes them.

Groq's Global Zero Data Retention (ZDR) setting is enabled for the operator's Groq organization. According to Groq, this prevents retention of AI inputs and outputs for system reliability and abuse monitoring and disables features that require stored content. Groq still processes your question to provide an answer and collects usage metadata that does not include AI inputs or outputs. Retention required by law may still apply. See Groq's data-handling information.

Groq's published Services Agreement does not permit using AI inputs or outputs to train or fine-tune models unless the customer explicitly grants permission or requests it. See Groq's Services Agreement, section 4.2.

Netlify provides hosting and backend processing. Groq's ZDR setting does not change Microsoft's or Netlify's operational records or retention policies, and it does not establish that previously retained records have been deleted. Each provider's records remain governed by its own policies and settings.

Availability and alternatives

AI reporting may be temporarily unavailable because of provider outages, usage limits, sign-in problems, or hosting issues. If an AI request fails, try again later or use One-Click Reports, the Visual Filter Builder, or the SQL editor. These options do not use Groq, but still depend on the website and public data sources being available.

For a time-critical report, keep another way to obtain and verify the information. Contact the deployment administrator if AI failures persist.

Report limitations and acceptable use

This service is experimental. Source data can be incomplete or delayed, and AI-generated reports can contain errors. The application checks generated SQL against permitted read-only queries on available datasets before running it in your browser. Those checks restrict what a query can do; they do not establish that it answers your question correctly.

A query can run successfully while using the wrong dates, agency, filters, or calculations. Verify AI-generated results against the source data or a known, independently checked report before using them in official reporting or operational decisions. Refer to the original data sources for licensing and reuse conditions.

Use the service lawfully. Do not bypass access controls or provider limits, disrupt the service, or submit information you are not authorized to share. Access can be restricted for misuse. Features and availability can change as the proof of concept develops.

Contact

For access questions, privacy concerns, or problem reports, contact the person who provided you with this proof of concept or your organization's deployment administrator.
